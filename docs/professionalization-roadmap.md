# План достижения профессионального уровня проекта

**Назначение:** довести репозиторий до цельной, проверяемой документации для локальных моделей на DGX Spark и инструментов разработки Windows 11/Android. Этот файл — план работ, а не доказательство выполнения тестов.

## Цель и критерий честной оценки

Целевой результат — **100/100 по опубликованной шкале приёмки**, а не обещание безошибочной работы на любой системе. Отдельно оцениваются качество документов и практическая проверка на оборудовании.

NVIDIA публикует разные vLLM-рецепты для Spark на 128 ГБ; выбирать и описывать нужно только ту ветку, которая соответствует фактической конфигурации.[20][65][66]

Для ComfyUI/Z-Image-Turbo есть отдельный Spark quick start; сценарий FLUX.2 Klein должен пройти проверку совместимости ComfyUI и workflow отдельно.[26][49][50]

## Политика Docker для данного устройства

Текущий пользователь не может обращаться к `/var/run/docker.sock` без `sudo`; Docker daemon активен. Допустимые варианты для будущего запуска:

1. оставить текущие права и выполнять Docker-команды с административным `sudo` по отдельно проверенной процедуре; или
2. осознанно разрешить добавление пользователя в группу `docker`, понимая уровень привилегий этой группы.

До выбора владельцем ни одну из этих мер не применять. `sudo docker info` — успешная проверка доступности daemon, но не проверка запуска модели.

## Автоматическое продолжение каждые 30 минут

После появления локального `WORKLOG.md` в папке проекта можно включить повторяющуюся задачу Hermes. Каждый запуск должен читать Worklog, выполнять только один ограниченный документальный шаг, проверять результат и обновлять Worklog. **Запуск моделей, изменение группы Docker и публикация непроверенных утверждений запрещены.** Если единственным оставшимся пунктом станет аппаратная проверка, задача должна остановиться и сообщить владельцу, а не обходить ограничение.

На момент создания этого плана расписание ещё не настроено.
